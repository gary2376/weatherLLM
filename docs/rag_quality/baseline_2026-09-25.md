# RAG 品質 Baseline（2026-09-25）

## 結果摘要

- Eval set：66 筆
- 有效評分：66 筆
- 查無 context：0 筆
- Faithfulness 平均：0.8906
- Context Recall 平均：0.5439
- Answer Relevancy 平均：0.5266

完整逐筆結果位於 `code/rag_quality/results_20260925.json`。

## 方法

從 RAG 查詢使用的同一份 BM25 語料，依縣市分層抽樣；22 個縣市各抽 3 筆，共 66 筆，固定亂數種子為 42。每筆文件以 `gpt-4o-mini` 生成一個自然語言旅遊問題，原始文件作為 ground-truth reference。

評估時，每個問題均呼叫現有的 `code/rag.py::query()` 取得 Top-5 context，再由 `gpt-4o-mini` 只根據 context 生成簡短答案，最後以 ragas 計算 Faithfulness、Context Recall、Answer Relevancy。LLM 與 embedding 評估呼叫使用 `DiskCacheBackend`，Eval 答案也寫入同一個磁碟快取，避免相同輸入重跑時重複付費。

`code/rag_quality/eval_set.json` 是一次性建立的固定測試集；後續比較沿用同一份資料，不重新抽樣或重新生成問題，確保不同版本的結果可直接比較。建置腳本偵測到既有檔案時會直接沿用；需要刻意重建時，逐筆問題生成也使用 `DiskCacheBackend`。

## 已知的度量限制

以下限制是從 `code/rag_quality/results_20260925.json` 的逐筆結果核對出來的。這表示 Context Recall 0.5439 與 Answer Relevancy 0.5266 不能直接等同於「RAG 檢索品質只有約五成」；部分低分來自測試集 ground truth 的定義及指標本身的計分方式。

### 泛用分類問句與單一 ground truth 不完全相容

目前每題只把當初抽樣到的一筆文件當成唯一 ground-truth reference，但不少生成問題是「某縣市有推薦的某類餐廳／景點／住宿嗎」這類可由多筆文件合理回答的泛用分類問句。當 RAG 找到同縣市、同類別的其他合理候選，Context Recall 仍可能因沒有取回當初抽樣的那一筆而得到 0 分。這種 0 分反映的是「沒有命中指定 reference」，不必然代表回答錯誤或檢索失敗。

- 問題：「苗栗市有沒有好吃的客家料理餐廳推薦？」回答推薦「川味仙客家菜館、福欣園餐館」，都是苗栗的客家餐廳；Faithfulness 0.50、Context Recall 0.00、Answer Relevancy 0.8959。高 Answer Relevancy 與零 Context Recall 並存，顯示回答切題，但沒有命中單一指定 reference。
- 問題：「找屏東恆春的舒適民宿，想體驗當地慢活氛圍。」回答推薦上仁民宿與竹安莊民宿；Faithfulness 1.00、Context Recall 0.00、Answer Relevancy 0.4942。回答受檢索內容支持，仍因未涵蓋指定 reference 而得到零 Recall。

### 誠實的「找不到／替代方案」會壓低 Answer Relevancy

Answer Relevancy 會從答案反推可能的問題，再以 embedding 相似度比較反推問題與原問題。當檢索 context 缺少指定資訊，而答案誠實說明「沒有找到」並提供鄰近或相似替代方案時，反推出來的語意容易偏離原始條件，因此即使答案沒有硬編，分數仍可能降到 0。這是指標對拒答／替代回答的已知敏感性，不能單獨解讀為 RAG 系統缺陷。

- 問題：「請推薦臺中市北屯區的登山步道或健身步道。」回答明確說參考資料沒有北屯區步道，並建議太平區的草嶺登山步道或新田登山步道；Faithfulness 0.50、Context Recall 0.00、Answer Relevancy 0.00。
- 問題：「請推薦我位於臺東縣的海邊民宿，有南歐風格的特色。」回答明確說參考資料沒有符合全部條件的民宿，再提供一簑煙雨民宿與邊境牧海民宿作為替代；Faithfulness 0.50、Context Recall 0.00、Answer Relevancy 0.00。

## 門檻決策

- Faithfulness：維持 ≥ 0.80；baseline 0.8906，高於原參考值。
- Context Recall：由原參考值 0.70 調整為當前回歸門檻 ≥ 0.50；baseline 0.5439。
- Answer Relevancy：由原參考值 0.70 調整為當前回歸門檻 ≥ 0.50；baseline 0.5266。
- 查無 context：維持 0 筆。

0.50 是依首輪實測設定的回歸防退步門檻，不代表 RAG 的實際正確率只有五成，也不應只靠調整檢索邏輯來追高分數。後續有兩條清楚的評估路徑：

1. 若目標是更準確衡量「是否命中唯一正解」，下一版 Eval set 應改用唯一指向性問題，在問題中包含足以鎖定單一文件的細節，再重新建立 baseline；此時才適合評估是否提高 Context Recall 與 Answer Relevancy 門檻。
2. 若保留目前的泛用分類問句與單一 ground truth，則把這份 Eval set 定位為「泛用查詢壓力測試」。在這種設計下，約 0.50 的 Context Recall／Answer Relevancy 是合理 baseline，應以同一固定測試集偵測版本退步，不必為達到 0.70 而勉強調整 RAG。

兩種路徑的分數不可直接混用；若未來重做唯一指向性 Eval set，應另立版本與 baseline，不覆蓋本次 66 筆結果。

## 執行備註

實際環境的 ragas 評分 API 會以 async 執行，原腳本傳入同步 OpenAI client 而失敗；已將 ragas 的 LLM 與 embeddings client 改為 `AsyncOpenAI`。另有一筆 Context Recall 結構化輸出超過預設 1024 tokens，已把 ragas `max_tokens` 提高為 4096。Eval runner 的答案生成與 Eval set builder 的問題生成也補上磁碟快取，builder 另加既有固定測試集保護。這些修正只處理套件相容性、輸出完整性與安全重跑，沒有改變抽樣、檢索、答案生成或三項指標的設計。
